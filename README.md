# Threat Hunting Investigation: Unauthorized Tor Browser Usage

## Project Overview

This project documents a threat hunting investigation conducted in **Microsoft Defender for Endpoint (MDE)** to determine whether unauthorized **Tor Browser** activity occurred on an Azure-hosted Windows workstation.

The investigation focused on correlating endpoint file, process, and network telemetry using **Kusto Query Language (KQL)**.

The hunt identified evidence showing that the user `samvulnlab1`:

- Had a Tor Browser portable installer present on the workstation
- Executed the Tor Browser installer
- Created Tor Browser files on the Desktop
- Launched the Tor-packaged `firefox.exe`
- Started the `tor.exe` process
- Established the Tor SOCKS proxy on `127.0.0.1:9150`
- Connected Firefox to the local Tor SOCKS proxy
- Generated successful outbound network connections from `tor.exe`
- Continued using the browser after Tor connectivity was established
- Created a file named `tor-shopping-list.txt`

**Final Determination:** Confirmed Unauthorized Tor Browser Usage

# Investigation Scenario

Management suspected employees might be using Tor Browser to bypass organizational network controls after unusual encrypted network activity was observed and anonymous reports indicated employees were discussing methods of accessing restricted websites.

The objective of the investigation was to determine whether Tor Browser had been installed or used and, if confirmed, reconstruct the activity using endpoint telemetry.

---

# Threat Hunting Hypothesis

If Tor Browser was installed and actively used on the workstation, evidence should exist across multiple telemetry sources.

I expected to identify:

1. Tor-related files appearing on the endpoint
2. Execution of a Tor installer or Tor-related processes
3. Execution of the Tor-packaged Firefox browser
4. Execution of `tor.exe`
5. Local communication between Firefox and the Tor SOCKS proxy
6. Outbound network activity generated by `tor.exe`

Rather than relying on a single indicator, I correlated **file, process, and network telemetry** to determine whether Tor was actually used.

---

# Investigation

## 1. Tor-Related File Activity

I began by searching `DeviceFileEvents` for filenames containing the string `tor` on `thlab-sam-01`.

```kql
DeviceFileEvents
| where DeviceName == "thlab-sam-01"
| where InitiatingProcessAccountName == "samvulnlab1"
| where FileName contains "tor"
| where Timestamp >= datetime(2026-10-06T01:44:05.3571493Z)
| order by Timestamp desc
| project Timestamp, DeviceName, ActionType, FileName, FolderPath, SHA256,
          Account = InitiatingProcessAccountName
```

```kql

| project Timestamp, DeviceName, AccountName, ActionType,

```

At approximately **01:47:16 UTC**, `samvulnlab1` executed:

```text
tor-browser-windows-x86_64-portable-15.0.20.exe
```

# 3. Tor Browser Execution

The next phase of the hunt was to determine whether Tor Browser was merely present or was actually launched.

I searched for execution of `tor.exe`, `firefox.exe`, and related Tor Browser processes.

```kql
DeviceProcessEvents
| where DeviceName == "thlab-sam-01"
| where FileName has_any ("tor.exe", "firefox.exe", "tor-browser.exe")
| project Timestamp, DeviceName, AccountName, ActionType,
          FileName, FolderPath, SHA256, ProcessCommandLine
| order by Timestamp desc
```

<img width="698" height="323" alt="Tor Browser process activity" src="https://github.com/user-attachments/assets/75ac41dc-bcab-4445-b689-3be0d5810d1b" />

### Findings

At approximately **01:48:26 UTC**, multiple instances of:

```text
firefox.exe
```

were launched from:

```text
C:\Users\Samvulnlab1\Desktop\Tor Browser\Browser\firefox.exe
```

The location is important because it distinguishes this executable from an unrelated standalone Firefox installation.

Additional Firefox child processes were subsequently created from the same Tor Browser directory.

The command-line telemetry referenced:

```text
C:\Users\Samvulnlab1\Desktop\Tor Browser\Browser\browser
```

providing additional evidence that these processes belonged to the Tor Browser installation.

Browser profile databases were also created, including:

```text
storage.sqlite
storage-sync-v2.sqlite
```

under the Tor Browser profile directory.

This activity confirmed that the browser was actively launched.

# 4. Tor Service Execution

At approximately **01:48:50 UTC**, `tor.exe` was executed from:

```text
C:\Users\Samvulnlab1\Desktop\Tor Browser\
Browser\TorBrowser\Tor\tor.exe
```

The process command line referenced Tor configuration files, GeoIP databases, its data directory, and two particularly important local services:

```text
ControlPort: 127.0.0.1:9151
SOCKSPort:   127.0.0.1:9150
```

The SOCKS proxy is especially important to the investigation because Tor Browser routes browser traffic through the locally running Tor process using this proxy.

At this point, the investigation had established:

```text
Tor files present
        ↓
Installer executed
        ↓
Tor Browser launched
        ↓
tor.exe started
        ↓
Local SOCKS proxy created
```

The remaining question was whether network traffic actually passed through Tor.

---

# 5. Tor Network Activity

I searched `DeviceNetworkEvents` for connections initiated by `tor.exe` and the Tor-packaged `firefox.exe`.

```kql
DeviceNetworkEvents
| where DeviceName == "thlab-sam-01"
| where InitiatingProcessAccountName != "system"
| where InitiatingProcessFileName in ("tor.exe", "firefox.exe")
| where RemotePort in ("9001", "9030", "9040", "9050", "9051", "9150", "80", "443")
| project Timestamp,
          DeviceName,
          InitiatingProcessAccountName,
          ActionType,
          RemoteIP,
          RemotePort,
          RemoteUrl,
          InitiatingProcessFileName,
          InitiatingProcessFolderPath
| order by Timestamp desc
```

## Firefox Connected to the Tor SOCKS Proxy

One of the strongest pieces of evidence appeared at approximately:

```text
2026-10-06 01:49:14 UTC
```

The Tor-packaged `firefox.exe` successfully connected to:

```text
127.0.0.1:9150
```

with:

```text
ActionType: ConnectionSuccess
```

This connection directly correlates the browser process with the local SOCKS proxy established by `tor.exe`.

The observed communication path was therefore:

```text
Tor Browser / firefox.exe
          │
          ▼
   127.0.0.1:9150
     SOCKS Proxy
          │
          ▼
       tor.exe
          │
          ▼
  External Connections
```

This provided substantially stronger evidence than simply identifying Tor-related files on disk.

---

## Failed Port 9001 Connection

At approximately **01:49:25 UTC**, `tor.exe` attempted to connect to:

```text
91.158.13.188:9001
```

However, Defender recorded:

```text
ActionType: ConnectionFailed
```

Therefore, this event represents an **attempted connection**, not a successful connection.

The successful outbound connections observed immediately before and after this event provide separate evidence that `tor.exe` had active external network connectivity.

# Evidence Correlation

No single event was used to determine that Tor Browser had been used.

Instead, the conclusion was reached by correlating three independent telemetry sources:

```text
DeviceFileEvents
      │
      ├── Tor installer observed
      ├── tor.exe created
      ├── Tor Browser shortcuts created
      └── Browser profile files created
                │
                ▼
DeviceProcessEvents
      │
      ├── Installer executed
      ├── Tor Browser firefox.exe launched
      ├── Browser child processes created
      └── tor.exe launched
                │
                ▼
DeviceNetworkEvents
      │
      ├── tor.exe generated external connections
      ├── Firefox connected to 127.0.0.1:9150
      └── Continued network activity observed
                │
                ▼
       CONFIRMED TOR USAGE
```

This correlation distinguished **actual Tor Browser usage** from simply having an installer or Tor-related files present on the workstation.

# Investigation Summary

The threat hunt identified **high-confidence evidence of unauthorized Tor Browser usage** on workstation `thlab-sam-01` by account `samvulnlab1`.

The investigation reconstructed a clear sequence of activity.

The Tor Browser portable installer was first observed in the user's Downloads directory. The installer was subsequently executed, after which Tor Browser components were created under the user's Desktop.

The Tor-packaged `firefox.exe` was then launched, followed by multiple browser child processes and creation of Tor Browser profile databases.

At approximately **01:48:50 UTC**, `tor.exe` started and configured a local SOCKS proxy on:

```text
127.0.0.1:9150
```

Successful outbound network connections from `tor.exe` began approximately 15 seconds later.

Most importantly, the Tor Browser `firefox.exe` process successfully connected to the local Tor SOCKS proxy at:

```text
127.0.0.1:9150
```

This correlated the browser session directly with the running Tor service and confirmed that the application was not simply installed—it was **actively being used**.

Additional browser processes continued to execute after Tor connectivity was established.

At approximately **02:00:15 UTC**, `tor-shopping-list.txt` was created on the user's Desktop. The filename is relevant to the investigation; however, the available telemetry does not reveal the contents of the file. Therefore, no conclusion was made regarding what information it contained or its intended purpose.

Similarly, the investigation confirms Tor usage but does not establish exactly which websites or services the user intentionally accessed through Tor.

### Final Determination

**Finding:** Confirmed  
**Activity:** Unauthorized Tor Browser execution and use  
**Device:** `thlab-sam-01`  
**User:** `samvulnlab1`  
**Confidence:** High

# Response Taken

Following confirmation of unauthorized Tor Browser usage:

- The affected workstation `thlab-sam-01` was isolated.
- The activity was documented.
- The user's direct manager was notified.

These actions contained the endpoint while allowing the findings to be escalated in accordance with the scenario's acceptable-use and security requirements.

# Key Takeaway

The strongest finding in this investigation was not simply the presence of `tor.exe`.

By correlating **file creation, process execution, and network telemetry**, I was able to reconstruct the activity from the initial appearance of the Tor installer through active Tor Browser usage.

The relationship between:

```text
firefox.exe → 127.0.0.1:9150 → tor.exe → external network connections
```

provided high-confidence evidence that the Tor Browser was actively functioning on the workstation.

The investigation also reinforced the importance of distinguishing **observed evidence from assumptions**. For example, the connection to `91.158.13.188:9001` was recorded as failed, and the contents of `tor-shopping-list.txt` were not available. Those limitations were documented rather than inferred beyond what the telemetry supported.
